## Behavior

- A runtime advertises `"suspend"` in `InitializeResponse.features` to opt in.
- A negotiated handler may return a suspend outcome; it round-trips with
  correlation key, wait type, expected signal, deadline, and payload schema.
- An unnegotiated suspend is returned as a controlled
  `unsupported_suspend_outcome:` failure, never an empty success.
- A resume is a fresh Execute carrying the same logical operation ID and a new
  attempt ID, with cause, signal name, delivery ID, and payload.
- Duplicate resume deliveries are delivered each time; `delivery_id` is the
  idempotency key the capability dedupes on.
- A client that does not know the field ignores `suspend`; legacy result/error
  behavior is unchanged.
- The stdin/stdout JSON transport rejects a suspend explicitly because it
  cannot represent one.
