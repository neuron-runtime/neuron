# Defect repair — T-021

status: fixed
lease: application/internal/acceptance/**

## Reproduction

- `GOWORK=off go test -count=1 -timeout 120s -run 'TestR4_24SigKillAfterCompletion' ./internal/acceptance` (cwd `application`), before any edit — the test binary hung; the process was killed by the 2m timeout and the goroutine dump showed `(*runtimeSession).stop` blocked on `<-s.done` (old `harness_test.go:436`) inside the `t.Cleanup` registered by `startRuntime` (~`:383`). Deterministic, not environmental.
- Second, independent failure surfaced after the harness fix, in `TestR4_24SigKillRecoveryVerifiesExecutionState` at `neuron build`:
  `capability runtime integrity conflict: acctest:blocking@1.0.0 already installed with digest sha256:2c06277f…, refusing to replace with sha256:9c46f591…`.
- Confirmed empirically that the same fixture source built in two different directories produced two different binaries:
  `go build -o blocking .` in `/tmp/opencode/br1` → `01af07fb…`, in `/tmp/opencode/br2` → `35994cfc…`.

## Root cause

Two distinct defects, both in the acceptance package:

1. `application/internal/acceptance/harness_test.go` — `runtimeSession.stop` was not idempotent. The old `stop` (~`:426-438`) read `<-s.done` on every call and closed the session, while `startRuntime` also registers `t.Cleanup(session.stop)` (~`:383`). A test's deferred `stop()` drained the single buffered `done`, so the later cleanup `stop()` sent SIGKILL and blocked forever on the already-consumed channel.
2. `application/internal/acceptance/testdata/blockingruntime/build.sh:4` — `go build -o blocking .` without `-trimpath` embeds the absolute build directory in the binary. Two acceptance tests (`cancel_test.go`, `r4-24_sigkill_test.go`) install the same identity `acctest:blocking@1.0.0` into the shared provider store from different project roots, so the second install had a different content digest and the store correctly refused to replace an immutable artifact (`application/capabilityruntime/installer.go:63,100`).

## Fix

- `application/internal/acceptance/harness_test.go`: added `stopOnce sync.Once`; `stop()` (SIGINT, escalate to SIGKILL after 10s) and `kill()` (immediate SIGKILL crash simulation) both funnel through `shutdown(abrupt bool)`, which signals at most once and reaps `done` exactly once; added `listExecutions`/`waitForExecutions` helpers that read `GET /v1/instances/{id}/executions` with the runtime bearer token.
- `application/internal/acceptance/r4-24_sigkill_test.go`: rewritten. Both tests set `NEURON_EXECUTION_DURABILITY=durable`, kill the runtime, restart it, and assert API-observed execution state. `TestR4_24SigKillAfterCompletion` asserts the completed execution keeps its ID and unchanged `completedAt`. `TestR4_24SigKillRecoveryVerifiesExecutionState` drives a blocking capability, kills the runtime mid-execution, restarts, and asserts the same execution ID reaches `completed` with exactly one execution.
- `application/internal/acceptance/testdata/blockingruntime/build.sh`: `go build -trimpath -buildvcs=false -o blocking .` so the same fixture source yields byte-identical artifacts regardless of project root, making the shared-identity install idempotent instead of an integrity conflict. Verified: both `/tmp/opencode/br1` and `/tmp/opencode/br2` now produce `2f1a65b0…`.
