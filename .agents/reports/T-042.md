## Root cause
- `nore/internal/execution/dispatch_intent_test.go:227` (before fix) — the concurrent-claim test deliberately used a **5ms** lease. The winner stored `LeaseExpiresAt = now + 5ms`; under `-race` scheduling/CPU contention the loser's `claimDispatchIntent` transaction could read the record only after that window elapsed, so `dispatchIntentClaimable` (`nore/internal/execution/store.go:699-707`) treated the winner's claim as expired, the loser's compare-and-swap succeeded against the unchanged value, and both goroutines reported `won == true`, failing the assertion at `dispatch_intent_test.go:262`. The production CAS/lease logic is sound; the sibling test using a one-minute lease never flaked. This was a test-synchronization defect, not a production or scheduler defect.
- `TestStoppedCapabilityPublishesCancellationNotFailure` — root cause not established; no local reproduction and no verbatim failure text in the repository. No speculative change made.

## Fix
- `nore/internal/execution/dispatch_intent_test.go:226-231` — replaced the 5ms lease with `time.Minute` so the winner's claim is still live when the loser performs its check. This makes the one-winner/one-loser phase deterministic while leaving the concurrency and both claims intact.
- `nore/internal/execution/dispatch_intent_test.go:314-330` — replaced `time.Sleep(20 * time.Millisecond)` with an explicit expiry fixture: read the stored intent, set `LeaseExpiresAt` to a time one second in the past, write it back through the store, then claim via the unchanged public `ClaimDispatchIntent` API. This preserves the recovery/expiry coverage without any wall-clock race.
- No production code changed; `store.go` untouched. No `t.Skip`, retry loop, weakened assertion, or increased timeout used.

## Regression test
- `nore/internal/execution/dispatch_intent_test.go:216` — `TestConcurrentClaimDispatchIntentWinnerLoserAndRecovery` is the regression test: it failed before the fix (2/100 `-race` runs) and passes after (`-race -count=50` and `-race -count=200`). All original assertions remain: exactly one winner, exactly one loser, winner owns the claim, loser returns `(nil, false, nil)`, stored owner matches, and the loser can claim after expiry. No new test was added because the defect was in this test's own synchronization, not in uncovered behavior.
