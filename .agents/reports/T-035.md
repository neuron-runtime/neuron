## Behavior
- Go and .NET now return `unsupported_suspend_outcome: ...` for a suspend combined with a non-empty result or a non-empty error, for `wait_type` other than `signal`/`timer`, for a timer with `deadline_unix_ms <= 0`, and for a signal with an empty `expected_signal`.
- No SDK branch silently prefers result, error, or suspend when the outcome is ambiguous.
- Repeated Initialize calls are monotonic in both SDKs: the response reflects the current handler declaration, while a previously advertised suspend capability remains negotiated for subsequent Execute calls.
- Valid signal and timer suspends still round-trip unchanged, and existing legacy result/error behavior is unchanged.
