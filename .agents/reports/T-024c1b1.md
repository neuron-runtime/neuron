## Root cause

- `nore/internal/execution/scheduler/timer_poller.go:148` — in the `state.WaitUntil.After(now)` branch, the code logs that the timer must be left intact but calls `s.discardClaimedTimer(ctx, timer.Key, owner)`, which deletes the very timer the future snapshot deadline still depends on (`timer_poller.go:247-251`). The action contradicts the branch's comment and log message.

## Fix

- `nore/internal/execution/scheduler/timer_poller.go:148` — changed `return 0, s.discardClaimedTimer(ctx, timer.Key, owner)` to `return 0, nil`. The claimed timer is no longer deleted when the snapshot deadline is still in the future; the warning log and all surrounding behavior are preserved. This is the smallest change that restores the stated contract: a claimed due timer conflicting with a still-future snapshot `WaitUntil` remains intact until the reconciliation slice.

## Risks and limitations

- The poller still has no production caller; behavior is exercised only by tests (see ADR 0003 D4). This fix does not change that.
