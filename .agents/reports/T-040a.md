## Implemented

- `Execution.RecoverableDispatch` accepts both `StatusRunning` and `StatusWaiting`.
- Recovery re-derives execution status with `refreshStatusLocked()` at the end of dispatch recovery.
- Recovery documentation records that the method is single-shot and not idempotent; exactly-once dispatch depends on the scheduler's clear/commit/publish sequence.
- `Scheduler.RecoverExecution` admits `StatusWaiting` instead of returning early.
- The corruption branch now fails only when unfinished work is neither running nor legitimately waiting, using `WaitingCapabilities()` and `UnfinishedCapabilityCount()`.
- Added execution-boundary tests for elapsed timer/deadline waits, elapsed retry waits, non-due signal waits, and nil `WaitUntil`.
- Added scheduler-boundary tests for no-failure healthy waits, persisted `StatusWaiting`, exactly-one elapsed dispatch, and mixed wait sets.
- Extended the nil-`WaitUntil` execution test to assert the re-derived status when a runnable sibling exists.
